# DS-2: Version history

Part of epic `doc-sharing` (see PRD.md).

## Intent

Every save of a document keeps what was there before, so a bad edit can be undone. Users can list
a document's versions (newest first), open one, and restore it. Restoring snapshots the current
content first, so a restore can itself be undone.

History routes follow the same access rules as the document itself.

Version ids come from the shared `newId()` helper, which should produce ids that sort by creation
time so listing by id is chronological; ids must stay unique when several app instances run
(`WORKER_ID`).

## Definition of done

- `saveDocument` records a version before every update.
- `GET /documents/:id/versions`, `GET /documents/:id/versions/:versionId`,
  `POST /documents/:id/versions/:versionId/restore`.
- Prisma schema: `DocumentVersion` (cascade-deleted with its document).
- `newId()` is time-ordered.
