# DS-1: Workspaces

Part of epic `doc-sharing` (see PRD.md).

## Intent

Let users share documents with a team. A user creates a workspace and becomes its owner and first
editor. The owner adds members as `viewer` or `editor` and removes them. A removed member keeps
the documents they own, but those documents leave the workspace with them. A document can be created
in a workspace the creator edits in.

Access to a document: the owner can do anything; workspace editors read and edit; workspace
viewers read; only the owner deletes. Read and write access now differ, so the single
owner-only check on document routes is replaced by an explicit access level per route.

`GET /documents` lists the user's own documents plus those in their workspaces. `GET /documents/:id`
also returns `sharedWith`: name, email and role of each member of the document's workspace.

## Definition of done

- `POST /workspaces`, `PUT|DELETE /workspaces/:workspaceId/members/:userId` (owner only).
- `GET|PATCH|DELETE /documents/:id` enforce read/write/own access; everyone else gets 404.
- `POST /documents` accepts an optional `workspaceId` (creator must be an editor there).
- Prisma schema: `Workspace`, `Membership`, `Document.workspaceId`.
